# Part C — text analysis

Copy `.env.example` to `.env` in the project root and set `GEMINI_API_KEY`.
Set `GEMINI_MODEL` to a structured-output model available to your account. The
default is `gemini-3.8-flash`; free-tier availability and quotas depend on your
Google project. Existing environment variables take precedence over `.env`.

From the project root, with the virtual environment activated:

```powershell
python -m uvicorn src.api.main:app --reload
```

Open http://127.0.0.1:8000/docs and try `POST /analyze`:

```json
{"text": "The onboarding call was helpful but the dashboard still feels slow and confusing."}
```

A successful response uses the PDF page 3 contract:

```json
{
  "sentiment": "mixed",
  "topics": ["onboarding", "dashboard performance", "usability"],
  "summary": "Positive experience with onboarding support, but the dashboard is seen as slow and hard to use."
}
```

Wording is generated by Gemini, so topics and summary can vary. Sentiment allows
positive, neutral, negative, and mixed. Pydantic rejects extra fields, invalid
types, empty topic names, and blank or multiline summaries. Blank or invalid
requests return 422 without calling Gemini.

The service sends the JSON schema in Gemini's JSON output mode, then validates
the raw JSON with Pydantic. An empty, malformed, or invalid model response gets
exactly one retry; a second failure returns 502 with a clean error. Provider
failures return 502, timeouts 504, and missing configuration, connection problems,
or quota limits 503. Provider error details and API keys are not returned.
SDK transport retries are disabled; each model call has a 30-second timeout.

Google's native `google-genai` SDK is used as agreed. The provider call lives in
`service.py`, separate from the API and schemas, so it can be replaced later.

Run the offline service/API tests without an API key:

```powershell
python -m unittest src.llm.test_analysis
```
